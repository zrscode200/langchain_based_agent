# Communication material

Demo and meeting material. **Nothing here is part of the product**, nothing in the workspace or
the connectors reads it, and the suite does not cover it. Delete the folder and the companion is
unaffected.

| | |
| --- | --- |
| `overview.html` | **Full version, 25 slides in five parts** — orientation, the skills, the instruction architecture, the contributors, the tools. Written to be read at your own pace rather than presented. |
| `overview-short.html` | **Short version, 11 slides** — the same material cut to what it is, what you can ask it, the layers, the roles, delegation, the connectors, and where to look. |
| `diagrams/*.mmd` | Mermaid sources for the diagrams that are genuinely graph-shaped. |

Both decks are single self-contained files — no dependencies, no network. In a browser: `←` `→` to move, `a` to flatten into one scrolling page, `p` to print.

The short version is **generated by selecting slides from the full one**, so edit `overview.html` first and re-cut rather than editing both.

## Editing a diagram

The SVG is inlined into `overview.html` so the deck stays self-contained. To change one, edit the
`.mmd`, regenerate, and re-inline.

```sh
npm install -g @mermaid-js/mermaid-cli     # local tool, NOT a repo dependency
mmdc -i diagrams/delegation.mmd -o diagrams/delegation.svg -b transparent
```

Or paste the `.mmd` into <https://mermaid.live>, which needs nothing installed.

Two things learned the hard way, worth not repeating:

- **Mermaid source cannot live in an HTML comment.** Its arrow syntax `-->` is also the HTML
  comment terminator, so the source escapes the comment and renders as visible text.
- **Mermaid is worse than CSS for anything that is not a graph.** Diagrams of the four peer
  skills and of the instruction layers were tried in Mermaid and were clearly worse — auto-layout
  collided the edge labels and destroyed the peer symmetry that made the point. Those stayed as
  CSS grids in the deck. Mermaid earns its place where there is a decision or a flow.
