# ICH consulting scenarios

Fixed, synthetic evidence packets for offline evaluation. No observation here
comes from MK-6070, MUSE, a patient, or an actual manufacturing operation. Values,
record identities, dates, and scientific premises are invented test inputs.
They must never be promoted into a real program workspace.

Use these to examine scientific usefulness as well as the semantic blockers in
[the evaluation contract](../../README.md). An instruction review is not a model
run; a model run outside the actual host does not test its routing, tool calls,
permissions, or persistence implementation.

## Run a case

1. Use an isolated session/workspace and supply only the selected input file,
   the candidate root instructions, applicable skill, and accessible shared
   references. No copied real-program artifacts. The packet's synthetic
   coordinate substitutes for real-program recovery in these exercises.
2. Do not give the model [the reviewer rubric](reviewer-rubric.md), other case
   outcomes, or the parent's proposed answer. In an automated harness, mount
   only the permitted packet and instructions, not this evaluator directory.
3. Answer the packet's scientist request. All represented records and their
   limitations are given. Treat their statements as scenario facts, while
   distinguishing observations, plans, and interpretation.
4. No live connectors, network calls, persistence to real program state, or
   installs. Local guideline synthesis is available; if exact official wording
   matters and is unavailable, say so. Do not claim to have opened official text.
5. Retain the candidate revision, model/runtime identity, supplied files, tool
   availability, actual answer/trace, and the reviewer's rationale in a disposable
   evaluation output location outside the source. Record material findings in the
   hub ledger when used for acceptance. Do not put observed answers into inputs.

| Case | Input | Question exercised |
| --- | --- | --- |
| G1 | [Upstream control](g1-upstream.md) | Explain a strategy and assess an omitted release test from a defined evidence basis. |
| G1b | G1 followed by [changed input](g1b-input-change.md) | Requalify only the relationship affected by a new input condition. |
| G2 | [Control options](g2-options.md) | Recommend a conditional preference and explain tradeoffs without inventing risk scores. |
| G3 | [Analytical concern](g3-analytical.md) | Interpret an existing contrast before proposing another study. |
| G3b | Fresh G3 with the replacement record in [capability variant](g3b-capability.md) | Change the inference when the contrast's measurement basis changes. |
| G4 | [Development stage](g4-stage.md) | Apply scientific principles without importing inapplicable formal expectations. |
| G5 | [Manufacturing comparison](g5-comparison.md) | Give a supported bounded comparison without a blanket comparability/approval status. |

For G1b, retain the original answer and provide the follow-up as the next turn.
For G3b, replace record A3 before supplying the packet to a fresh session; do not
show both conflicting versions as simultaneously valid. These are two distinct
perturbation designs, not interchangeable procedures.

Also rerun a case with record order reversed and cosmetic document-title changes.
Keep scientific content fixed. Evaluate whether those changes alter the conclusion
without a scientific reason. These runs are not performed merely by writing this
fixture set.
