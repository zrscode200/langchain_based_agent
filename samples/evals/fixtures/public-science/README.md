# Public-science consulting scenarios

Five fixed synthetic cases assess whether public scientific information improves
consulting reasoning. These are invented programs and publications, not real
provider findings. They must never enter a real program workspace or be searched
as if their identifiers existed. Connector contract fixtures live separately in
`tools/fixtures/public_science/captured/` and contain actual public responses.

Use the candidate root instructions, relevant skill and external retrieval guide
with one selected input. Do not supply the reviewer rubric. The case supplies
program evidence and simulated public-source material as clearly labeled inputs.
An evaluator may reveal a source's detailed passage only when the model requests
that read. Record the request and what was supplied; do not claim a real MCP call.
No network, live internal data, new dependencies or program persistence is needed.

| Case | Input | Purpose |
| --- | --- | --- |
| P1 | [Narrow question](p1-narrow.md) | Answer from sufficient qualified evidence without needless expansion. |
| P2 | [Incomplete framing](p2-framing.md) | Recognize a measurement perspective missing from the proposed cause. |
| P3 | [Inapplicable mechanism](p3-applicability.md) | Reject a literature mechanism whose necessary conditions are absent. |
| P4 | [Abstract and methods](p4-full-text.md) | Narrow an attractive abstract using methods and table context. |
| P5 | [Reuse and update](p5-reuse.md) | Reuse qualified exploration, then reopen the affected part after a change. |

Use the [separate rubric](reviewer-rubric.md) to assess scientific consequences,
not search counts, paper counts, exact wording or mandatory hypothesis lists.
Keep actual answers, supplied files, candidate revision, model/runtime, available
tools and evaluator judgments outside the inputs. A written packet is not an
executed evaluation; a prompt exercise is not an end-to-end host admission.
